# 流程验收与机器负例

自动化先运行 `node --test docs-notes-toolkit/tests/cli.test.mjs`。测试使用临时项目和真实命令退出码；不需要原仓库、联网或第三方包。下列应用场景再检查机器不能判断的理由、事实和权限。

## 1. 初始化与重复接入

正常：在副本复制完整工具包，运行 init，再运行 bootstrap gate；保留既有 agent 指令，复用配置中的 notes。再次 init 不重复入口、不重置 ownership。

违规：冲突的既有导航不应被覆盖；未知参数、无效 JSON、目录越界、符号链接逃逸或重复入口段返回非零并带修复提示。Node 不可用时，不声称自动化接入成功。

人工：确认生成导航对真实读者有用、入口确实被 harness 读取，且没有把提案当业务能力。

## 2. 日常来源变化

正常：变更前 snapshot；修改已登记 sources 和详细文档，填 phase=update 的 JSON 报告，执行 update gate。若 source 变化不影响文档，针对该 source 写具体 unchanged 理由，评审合理性。

违规：来源变化但 doc 不变且无理由、文档变更未列 decision、缺报告/基准、阶段错、重复 topic、文档断链/模板残留/未知主状态，应失败。不能通过清空映射、事后 snapshot 或 `|| true` 放行。

人工：判断来源登记是否覆盖本次变更、文档是否真正准确，而不只是随意改字符。

## 3. 整理与历史冻结

正常：从可信前态将 active 记录移入 archiveRoot，正文只加日期和允许的链接机械重定位；报告新 path/from/action=archived/reason，修复入站引用，curate gate 通过。

违规：已归档文件改一字/删除、proposed 或 rejected 直接归档、归档时改写事实、无报告删除、未修复入站链接，均应失败。check 不含前态，不能单独证明历史没变。

人工：仍约束安全的旧记录不归档；机械日志无删除权限只建议处理；部分替代保留有效内容；机器不能代替这些价值与授权判断。

## 4. 知识晋升与证据

正常：基准及当前来源均为 active；目标是本次有变化的 docs 页面，报告有实际 evidence 路径；来源仍保留理由；promote gate 通过，另查目标事实与操作。

违规：proposed 来源、同次改 active 洗状态、目标不变/归档、证据路径缺失、来源被删或报告为空，应失败。存在一个证据文件不证明它支持正文。

人工：当前规则和真实步骤进入正式文档；理由与替代方案留笔记，未实现方案仍 proposed。输入只有“有已验证步骤”却无具体步骤时，只做待补草稿，不编造操作、失败语义或负责人。

## 5. 复制与 CI 接线

把完整目录改名复制到另一临时项目，在不同工作目录通过明确路径运行相同 CLI 与测试。不得依赖来源仓库、全局包、工作目录偶然路径或下载依赖。

授权接入 CI/hook 后，用一个已知违规样例验证顶层步骤非零；仅叶子检查失败不证明顶层阻断已生效。可信基准由受控前态提供，不由修改后的状态替代。测试后撤销负例，保留执行结果与未覆盖项。
