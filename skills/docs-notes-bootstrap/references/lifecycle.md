# docs 与决策笔记的最小维护机制

这是一套可迁移方案，不要求原项目的语言、目录或工具。四个 skills 共同读取本文件；所有实际路径、状态映射和检查入口以目标项目的维护配置为准。项目已有规则优先，不能未经授权迁移历史体系。

## 信息分工

| 内容 | 归属 | 更新方式 |
|---|---|---|
| 已实现的行为、限制、使用与故障恢复 | 正式 docs 或已有包 README | 随行为变更更新现状，用源码、测试或实际操作核实 |
| 问题、选择理由、真实替代方案、代价、负面保证 | 当前决策笔记 | 实现位置变化时修正事实；决策反转则新建并关联，不改写旧结论 |
| 尚未决定或尚未实现的方向 | proposed 笔记或项目原有规划工具 | 不写入 docs 的现状段；未实现不等于被否决 |
| 当次尝试、调试转录、机械编辑日志、无长期价值待办 | 临时工作记录或任务系统 | 不自动晋升为决策记录；按项目规则清理 |
| 能从代码精确枚举的字段、签名、命令帮助 | 源码或已有生成器的输出 | 有生成器则先改源再生成；没有生成器可人工维护，不强制引入工具 |
| 每次任务都必须遵守的简短动作 | 项目 agent 入口 | 只放触发与链接，不复制整套规范 |

一项当前事实有一个详细所有者。入口和高层概览链接到它，必要的局部前置条件仍保留。笔记可以保留“为何选择五次重试”的理由，但具体默认值与完整用法只在当前配置参考中维护，笔记指向该参考。历史决策证据不必为避免字面重复而删除。

## 状态与历史

- `proposed`：方案或工作未完成；允许验收条件、风险与明确的未知。
- `active`：已实施且理由仍有未来指导价值；与实现一致，使用现在时。`accepted` 在一些项目中只表示批准，不能未经映射当作已实现。
- `rejected`：有明确否决结论与真实原因；仍能阻止反复犯错时可保留为当前检索材料。
- 归档是历史身份，不自动等于状态变更。默认只归档已经完成、理由不再约束未来工作但仍有历史价值的 active 记录。继续有用的旧记录不归档。
- 未完成提案没有明确放弃决定时保持 proposed。被明确放弃时记录否决理由；不靠过期时间代替决策。
- 部分替代保留旧记录中的有效部分，双向关联；完全替代须先保存独有理由、代价、否定保证、验证要求与未解决问题。
- 默认归档策略为 `frozen-body`：移动前完成必要的现状修正；归档事务允许移动、添加历史标记、修复入站链接，以及只为保留原目标而机械重定位出站相对链接，不趁机改写决策或历史事实。随后冻结，归档后不继续维护事实或出站链接，不把它作为当前行为依据。已有政策若连机械重定位也禁止，采用路径不变的历史标记方案或报告移动受阻，不能破坏原政策。
- 机械笔记可提出删除建议；没有明确删除权限不得删除。归档不作为绕过删除权限的垃圾桶，暂留并报告也可。

## 防止过时的执行闭环

每次代码或配置变更先找受影响 docs 和当前笔记，再核对事实源；同步修改放在同一变更中。若只能写文档却发现实现不符，报告差异，不擅改代码也不把期望伪装成事实。

在项目 maintenance.json 的 ownership 维护“topic → document → sources”映射，人工入口链接它，不重复维护另一份机器登记。小项目按页面登记即可；未登记来源不在自动失效覆盖内。新增事实先找所有者；来源变而文档不变要在 JSON 报告给出 unchanged 理由，机器只验证记录存在，不判断理由正确。

随包 Node CLI 负责配置、入口、受支持链接/状态/占位符检查；变更前 snapshot，变更后用本次 JSON 报告执行阶段 gate。不能以人工核对替代失败门禁；缺 Node 则报告自动化阻塞。项目的语义、代码标识和操作验证另按实际能力执行，未运行写未运行。校验器不替代真实性判断。

过时检查的触发来自行为变更、重命名、移除功能、冲突报告、重复检索失败，以及发布前或维护者主动审计。可选周期审计由项目自行采用；安装 skill 并不会自动安排任务或创建 hooks。

## 稳定知识晋升判据

内容可进入 docs，当且仅当：它服务反复出现的读者任务或当前参考需求；对应实现或可执行操作已经存在；适用范围、失败/限制、维护所有者和核实方式明确。稳定不是达到某个年龄，也不意味着不再变化。

晋升单位是知识条目，不是整份笔记：操作步骤去 tutorial/runbook，当前规则去 reference，理由与真实替代方案留笔记，未实现方向仍是 proposed。先补目标文档并验证，再在源笔记用链接替换被迁移的详细说明，最后决定是否归档；晋升本身不触发自动归档。

## 通用必需与可选适配

必需机制是分工、身份、详细所有者、证据、更新、理由、权限和诚实验证。本工程化版本另需 Node.js 20+、机器 JSON 和阶段门禁；不依赖第三方包或来源仓库。路径、状态值、多人审批、双语、生成器、网站和预算仍可配置；CI/hook 不自动安装，但未接入便不能声称自动强制。历史冻结比较依赖可信前态，不是防恶意篡改签名。
